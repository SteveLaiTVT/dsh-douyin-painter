# PDF 直播荧幕台视觉落地

参考：用户提供的《每日主题大赛 · 直播荧幕台.pdf》，5页，1080×1920。

舞台采用同一竖屏骨架，按收词、候选/投票、生成、作品展示切换主任务。主播操作台沿用相同色彩、等宽数字、细边框与紧凑信息行；房间号、主题、音色和流程控制保留在主播侧。

视觉基准：背景 #0A0B0D、表面 #121519、焦点 #FF5B45、通过/连接 #00C2A8。参考投屏安全区为左右64px、顶部120px、底部230px。1080基准字号：标题88–104、倒计时118–132、正文28–34、标签24–26；窄屏等比例适配，较长主题允许换行。

保留已确定的比赛规则：最多3个候选，观众以投1/投2/投3决定赢家；平票和0票由主播裁定。PDF的TOP10、评审定名次及示意排行榜不替代该规则。数据只来自当前应用接收到的评论、候选、有效票和历史作品。不显示虚构在线人数或人为抬高票数。

生成接口没有逐帧进度事件，生成态用不确定进度和真实状态说明，不显示模拟68%、预计剩余13秒或已完成17/24帧。舞台不提供冒充抖音消息发送的输入框；观众在直播间发弹幕，主播在工作台代录。语音继续使用舞台点击授权播放与串行回执。

浏览器回归使用离线注入模型及采集源；视觉参考截图不代表真实比赛结果。参考渲染与验证图片存放在忽略目录 `.data/ui-reference/`、`.data/validation/`。

## 主持互动补充

Agent 从真实新评论中挑选值得回应的创意、问题和有趣聊天，维护最近全局回复及同观众上下文，避免换一个观众就重复同一句主持词。普通接话延续10秒最小调用间隔；纯投票和重复刷屏不触发回复。

同一主题的完整规则首次开场介绍，之后最多每180秒提醒一次；短轮次重新开场不重置该限制。规则提醒复用已有解说，不为定时提醒再次请求文本模型。暂停、关闭自动语音及语音积压时不追加规则广播，阶段必要的投票/揭晓指令仍可简短说明。
