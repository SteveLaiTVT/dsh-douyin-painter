# 已确认的直播共创工作流（本轮实现）

用户同意：DeepSeek推荐候选、主播可补选、UID弹幕投票决定画谁；AI按阶段开场、接住创意追问、投票时不拉票、出图等待接话、揭晓署名。主播掌握节奏并可暂停。最新补充：结果必须是真正生成的GIF动图；开场讲玩法；有趣发言用更合适音色朗读。

实现者取值：收词90秒、投票30秒，可提前推进；每10秒至多一次文本互动批次，单次一到两句，语音串行。参数可在本机工作台调整。缺UID不计正式票；一用户（source+room+uid）最后一票为准；仅本轮投1/投2/投3生效。采集断连/未开播时暂停正式投票，明确显示仅统计收到的票。平票/0票停在待主播裁定，不让模型暗中决定。开场由主播点按钮触发，应用启动不自动发付费请求。

模块：src/voting.js纯函数计票，src/workflow.js阶段与调度，src/conversation.js互动挑选和记忆，src/speech-queue.js单队列，Application保持API/业务/媒体。provider增添converse({theme,rules,phase,comments,history,signal})->{commentId,text,readOriginal:boolean}或commentId:null/text:''代表不回复；只允许真实commentId、同观众短上下文。OpenAI原生output_format:gif，6帧、200ms、size:auto；GIF preview拒绝则如实报错，绝不静默换PNG。保留显式静图兼容接口给已有模块测试。MiniMax speech-2.8-hd提供电台男主播/温暖闺蜜/清脆少女预设及音色选择，允许环境默认覆盖，不自动克隆。

UI：顶部主题和房间设置可折叠，主区域是比赛阶段、倒计时、当前问句、参与人数/评论回执、投票三卡及GIF舞台预览。主按钮开场收词/结束收词并推荐/开始投票/结束投票/揭晓作画（按阶段显示），主播补选和裁定在候选卡。AI接话开关、语音开关/音色与立即停止始终可用。舞台使用相同阶段大画面、昵称/贡献来源、真实生成状态和串行音频字幕。不使用假的生成百分比。

旧记录兼容，重启不自动恢复比赛、投票、队列或付费请求。旧单项操作仍保留为进阶控制。验证默认离线注入完整链路；真实GIF/语音质量另记，不冒充生成成功。
